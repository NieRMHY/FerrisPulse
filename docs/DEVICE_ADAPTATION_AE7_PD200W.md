# AE7 / PD200W 设备适配记录

2026-11-02，NieRMHY 提供 Windows 真机。源码基线：`4fcda58`。

## 设计与实现计划

1. 复现：Windows 能枚举接收器，但 FerrisPulse 未获得电量。
2. 从官方实现确认读取指令，限定 VID/PID、Usage 和报告长度后采集真机响应。
3. 实现两个独立内置只读驱动，通过注册表和 DeviceManager 接入，不在 UI 硬编码品牌。
4. 使用 DriverStateStore 按接收器和 TX 通道保存历史电量；无连接不生成假 0% 通道。
5. 回放真实帧、损坏帧和边界帧；Windows 编译、完整测试与再次真机轮询。

## 达尔优 AE7

- 接收器 `260D:1257`，固件名称 DAREU Receiver，制造商字符串 Compx。
- 精确端点：UsagePage `FF02` / Usage `0002`，Input=17，Output=17，Feature=0。
- 官方依据：<https://dr.dareu.com/products/1257/1257.json> 指定 FwType=2，
  <https://dr.dareu.com/js/device/jmdevice.js> 的 `GetBatteryStatus` / `CheckSum`。
- 旧通用引擎将该品牌分发到 CompX 64B Feature 查询，但实机控制端点为 17B Interrupt。
  此 PID 现在由 DareuAe7Driver 接管，并从通用引擎排除。

实际 TX（17B）：

```text
08 04 00 00 00 00 00 00 00 00 00 00 00 00 00 00 49
```

实际 RX（17B）：

```text
08 04 00 00 00 02 64 00 10 60 00 00 00 00 00 00 73
```

含 Report ID 的 byte[6] 是百分比，byte[7] 是状态（官方定义：0 非充电，1/2 充电）。
全帧字节和模 256 为 `55`。本机实测 100%、非充电；充电样本为协议合成测试，未宣称实测。

### 短暂静止与待机（2026-11-03 实测）

静止后电量命令可能不再回复，但接收器本身仍可立即响应官方 `CheckActive` 只读查询：

```text
TX: 08 03 00 00 00 00 00 00 00 00 00 00 00 00 00 00 4A
RX 活动: 08 03 00 00 00 01 01 03 FD 51 00 00 00 00 00 00 F7
RX 待机: 08 03 00 00 00 01 00 03 FD 51 00 00 00 00 00 00 F8
```

byte[6] 为活动位 0/1，整帧校验仍为 `55`。NieRMHY 移动 AE7 时，8 次电量查询均成功（约 3–5ms）；停止后活动位转为 0，电量查询不再响应。不能把“不回复电量”直接解释为接收器掉线，也不能据此推断整机深度休眠。

驱动先查询活动位；确认 0 时保留历史电量/采样时间，显示“接收器在线 · 待机”。活动位未知时显示“接收器在线 · 等待电量”，不假定已经休眠；活动时电量命令最多尝试两次。同进程 AE7 查询串行，不排空输入队列，不发送驱动模式或休眠设置写入。

`SupportsBatteryWakeRefresh` 能力让非主鼠标也保留 RawInput 唤醒监听。仅相同 VID/PID 的真实鼠标活动会触发目标驱动查询，不进入全品牌扫描；同一批高频输入合并，失败重试至少间隔 5 秒，已活动设备不重复查询。无关输入按句柄缓存为拒绝。查询后只替换相同 DeviceId 的记录，不改变另一只鼠标的电量、休眠或连接类型；局部发布也不能更新整组观察时间。日常定时轮询频率不变，待机或没有实时读数时 TrafficMonitor 仍显示 `--`。回归见 `test_ae7_standby_wake.ps1`、`test_mouse_wake_identity.ps1` 和 `test_targeted_battery_refresh.ps1`。

## 闪克 PD200W

- 实测接收器 `352F:040E`，Maono Wireless Mic RX。
- 精确端点：UsagePage `000C` / Usage `0001`，Input=64，Output=64，Feature=0。
- 官方依据：用户本机 Maono Link 4.0.88 的 MaonoDevicesInfo.txt、PD200XW.dll。
  原软件及 DLL 不随本项目提交或分发；本实现仅复现已确认的读取协议。
- 软件型号映射将 040E 指向 PD200W_RX。独立发送寄存器读取指令，
  不依赖 Maono Link 常驻，不录音，不访问语音或账号功能。
- 底层包首字节必须为 `C4`；官方上层缓冲的前导 `00` 不属于此 Windows HID 报告。

TX 查询（每帧补零至 64B）：

```text
C4 09 00 00 04 41 00 EE FE   # 连接状态
C4 09 00 00 04 42 00 ED FE   # 电量
C4 09 00 00 04 49 00 E6 FE   # 充电状态
```

实际 RX（每帧完整读取 64B，下列为非零数据所在前缀）：

```text
C4 0B 00 00 04 41 00 02 00 EA FE   # TX1 状态 2（在线），TX2 状态 0
C4 0B 00 00 04 42 00 3D 00 AE FE   # TX1 61%，TX2 未连接
C4 0B 00 00 04 49 00 00 00 E4 FE   # 当前非充电
```

byte[1..2] 为小端有效帧长。byte[4]=04 为读取。
从 byte[5] 起，每 4 字节为寄存器地址与 16 位值，均小端；电量值低/高字节分别对应 TX1/TX2。
有效帧末两字节是小端校验值，等于此前字节和的 16 位补数。
异步 `03` 通知、其他寄存器、长度错误和校验错误不能当成电量应答。

仅将连接状态 2 判为在线；第二通道及多接收器按独立身份保存。
仅实测充电状态 0，其他状态显示未知，不推测充电图标。双麦克风在线、充电与热拔插仍需额外真机覆盖。
新增 Microphone 分类位于枚举末尾，保留原分类持久化数值。

## 范围与复核

只支持上述实测 PID 和精确端点，不自动扩展到 AE7 有线、其他接收器或同品牌全系列。
只开放电量能力，关闭 DPI、回报率和音频设置控制。没有 EEPROM、配对、升级或配置写入。
查询不预先排空输入队列；在总超时和帧数上限内过滤异步通知，避免高频或无限读取。
超时保留历史电量和时间，但不把缓存当成当前充电状态。

验证入口：`build.bat`、`tests/test_ae7_pd200w_battery.ps1`、`tools/run_all_tests.ps1`。
回放测试不进行物理 I/O，真机轮询需单独执行两个驱动的 `QueryDevices`。
